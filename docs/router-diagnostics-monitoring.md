# Диагностика роутера: адаптация system-metrics dashboard

Исследовано 21 октября 2026 года.

## Что именно в источнике

Источник: [TheHive — Set Up Monitoring with Prometheus and Grafana](https://docs.strangebee.com/thehive/operations/monitoring/).

Это инструкция по наблюдаемости TheHive, а не библиотека виджетов. Она описывает
сбор метрик Kamon, экспорт в Prometheus и визуализацию в Grafana. Для системных
метрик рекомендован Kamon 2.x System Metrics, dashboard **12315**; для API —
**12317**; для Akka — **10776**. Второй пользовательский скриншот показывает
именно подход system-metrics: плотный обзор, отдельные секции и временные ряды.

Код TheHive/Kamon/Grafana не копировался. Реализована адаптация полезных
принципов на существующих procfs/RCI-данных панели.

## Реализовано

* Обзор: сегментированные шкалы CPU/RAM/swap, load за 1/5/15 минут, крупные
  значения приёма/отдачи, диска и температуры. На широких экранах он занимает
  одну компактную строку и не конкурирует по размеру с графиками.
* Сворачиваемые разделы «Обзор», «Подключение», «Нагрузка и ресурсы»,
  «Проверки и события». Существующие DNS, conntrack, интерфейсы, клиенты,
  процессы, LTE, ping и traceroute сохранены.
* Отдельный график load в числе задач: он больше не смешивается с процентами CPU.
  Шкалы load в обзоре нормированы на число ядер только визуально.
* Табличные min/max/среднее/P95/текущее, переключение рядов, подсказки.
  Среднее и P95 вычисляются по полученным точкам, не являются
  взвешенной по времени статистикой при смене частоты опроса.
* Обновление 5/15/30 секунд или пауза. Фоновая вкладка опрашивается не чаще
  раза в 30 секунд; ручное обновление работает и на паузе.
* История до 24 часов и до 17 280 точек только в текущей вкладке.
  Интервал выбирается по времени, не по предположению о частоте опроса;
  пропуски и длинные паузы не соединяются непрерывной линией.
* Состояния ожидания, неполной телеметрии и ошибки. Отсутствие данных
  не означает исправность; отсутствующая температура не превращается в 0 °C.
  Заполнение conntrack участвует в сводном предупреждении.
* JSON-снимок ресурсов и выбранной истории: явный список числовых полей,
  без IP/MAC, имён интерфейсов, клиентов, журналов, процессов и модемов.
* Отдельная обработка зависшего запроса ресурсов (12 секунд).
* Top‑5 потребителей загружается один раз; «Показать всех» переключает уже
  полученный список до 100 записей без нового запроса к роутеру.
* Load average получил встроенное объяснение: 1 минута — реакция сейчас,
  5 минут — сглаженная нагрузка, 15 минут — тренд; значение сравнивается с
  числом ядер роутера.
* Реальные пропуски сетевых измерений помечаются на графике и при наведении
  показывают длительность. Переход фонового опроса на 30 секунд не считается
  ложным пропуском.
* Исправлены ключи переключателей приёма/отдачи и единицы подсказок интерфейсов.

Новые циклические RCI-запросы, фоновые процессы, записи на диск роутера,
сторонние JS-библиотеки и дополнительные открытые порты не добавлены.

## Что полезно перенести следующим этапом

| Возможность | Как адаптировать | Почему не включено в текущий UI-редизайн |
| --- | --- | --- |
| Prometheus export | Опциональный read-only endpoint существующей панели, без отдельного listener | Нужны отдельное решение по аутентификации и перечень безопасных labels |
| Долговременная история | Внешний Prometheus на NAS/сервере; роутер только отдаёт ограниченный снимок | Не следует хранить постоянную БД метрик на маломощном роутере |
| Метрики API | Счётчики запросов, ошибок и histogram задержек; ограниченный набор route labels | Требует серверной инструментации; streams/WebSocket/long-poll нельзя смешивать с обычными запросами |
| Правила предупреждений | Порог + длительность + восстановление, затем интеграция с центром уведомлений | Единичный пик не должен создавать инцидент; температурные пороги зависят от модели |
| Dashboard переменные | Выбор WAN/VPN-интерфейса вместо суммы всего сетевого стека | Нужен согласованный источник истории интерфейсов; мосты/VPN могут учитывать одни байты повторно |

JVM heap/GC, Akka actors и VM hiccups из окружения TheHive не перенесены:
они не описывают Flask/Entware/Keenetic. Установка Kamon, Java, Prometheus
или Grafana **на роутер** для этой модали не требуется.

Температура показана без универсального аварийного порога. Сеть в обзоре
подписана как сумма интерфейсов, а не скорость интернет-канала.

## Проверки

* Runtime-тесты чистой модели: неизвестные значения, timestamp-фильтрация,
  поиск ближайшей точки, сводное состояние, приватность JSON.
* Playwright: desktop/tablet/mobile, светлая/тёмная темы, переключатели,
  сворачивание секций, геометрия header/body, пауза, восстановление и download.
* Существующие проверки DNS/RCI/procfs, модульной композиции и управления LTE.
